# 08 · 网络虚拟化详解

> 让 VM 互相通信、跟 host 通信、跟外网通信——同样一个目标，5 种实现路径。

## 学习目标

- 能说出 5 种网络拓扑的差别
- 知道 vhost-net 为什么性能更好
- 能用 OVS/macvtap 配置生产级网络
- 理解 SR-IOV 与设备直通的关系

## 1. 网络栈全景

```
客户机 OS（应用）
     │
     │ TCP/UDP
     ▼
客户机 NIC 驱动（virtio-net / e1000）
     │
     │ virtio 前端 → 后端（QEMU）
     ▼
QEMU 后端（virtio-net 或 vhost-net）
     │
     │ tap / socket
     ▼
宿主机内核协议栈
     │ (TCP/IP / bridge / iptables / OVS)
     ▼
物理网卡（NIC）
```

## 2. 五种模式回顾（lab05 跑过）

| 模式 | 适用 | 性能 | 复杂度 |
| --- | --- | --- | --- |
| user/NAT | 本地开发 | ★★ | ★ |
| bridge (virbr0) | 通用 | ★★★ | ★ |
| bridge (br0) | 生产 | ★★★★ | ★★★ |
| isolated | 隔离测试 | ★★★ | ★ |
| macvtap | 高性能 | ★★★★★ | ★★★ |

## 3. virtio-net 三种实现

### 3.1 用户态 virtio（默认）

```
客户机驱动 → virtio ring
             │
             │ (数据复制 + ioctl)
             ▼
QEMU 进程 → tap 设备
             │
             ▼
host 协议栈
```

**问题**：每次数据包 QEMU 进程要 read/write tap，开销大。

### 3.2 vhost-net（kernel 加速）

```
客户机驱动 → virtio ring（mmap 共享）
             │
             │（无 ioctl，零拷贝）
             ▼
vhost-net 内核线程 → tap 设备
             │
             ▼
host 协议栈
```

QEMU 不参与数据路径，只负责控制（KICK、call）。

**性能提升**：吞吐 ↑30%，延迟 ↓20%。

#### 启用 vhost-net

```xml
<interface type='bridge'>
  <source bridge='virbr0'/>
  <model type='virtio'/>
  <driver name='vhost'/>      <!-- 关键 -->
</interface>
```

### 3.3 vhost-user（在用户态 DPDK）

> 跳过 host 协议栈，由用户态进程（如 OVS-DPDK）直接处理数据包。

```
客户机 → 共享内存 → OVS-DPDK → 物理网卡（DPDK 驱动）
```

✅ **NFV / 高频交易场景**；
⚠️ 绕过 host 网络栈，配置复杂。

## 4. 多队列 virtio-net

让客户机每个 vCPU 一个收发队列，充分利用多核。

```xml
<interface type='bridge'>
  <source bridge='virbr0'/>
  <model type='virtio'/>
  <driver name='vhost' queues='4'/>
</interface>
```

VM 内：

```sh
ethtool -L eth0 combined 4   # 配 4 队列
```

> 性能：单队列 1Mpps，多队列可到 4-8 Mpps。

## 5. Bridge / OVS / macvtap

### 5.1 Linux Bridge

```bash
brctl addbr br0
ip link set br0 up
brctl addif br0 eth0
```

简单、低性能。

### 5.2 Open vSwitch（云环境标配）

```bash
# 装
sudo apt install openvswitch-switch

# 建桥
ovs-vsctl add-br ovsbr0
ovs-vsctl add-port ovsbr0 eth0
ovs-vsctl add-port ovsbr0 vnet0

# VLAN 隔离
ovs-vsctl set port vnet0 tag=10
```

### 5.3 macvtap

```bash
ip link add link eth0 name macvtap0 type macvtap mode bridge
ip link set macvtap0 up
```

QEMU 用：

```bash
-netdev tap,fd=3,id=hostnet0,vhost=on \
-device virtio-net-pci,netdev=hostnet0
```

`fd=3` 由外部程序（脚本）打开 macvtap 后传过来。

### 5.4 IPVLAN

比 macvtap 更省，VM 共用 MAC。

## 6. SR-IOV

让一块物理 NIC 暴露成多个「虚拟功能」（VF），每个 VF 直接给一个 VM。

```
┌─────────────────────┐
│  Physical NIC        │
│  PF (Physical Func) │
│  ├── VF0 ──── VM1   │
│  ├── VF1 ──── VM2   │
│  └── VF2 ──── VM3   │
└─────────────────────┘
```

VF 直接 DMA 到 VM 内存，几乎零开销。

### 启用

```bash
# 1. 确认网卡支持
lspci -vv -s 00:04.0 | grep SR-IOV

# 2. 配 VFs 数量
echo 4 > /sys/class/net/eth0/device/sriov_numvfs

# 3. 给 VF 配 MAC、VLAN
ip link set eth0 vf 0 mac aa:bb:cc:dd:ee:01
ip link set eth0 vf 0 vlan 10
```

VM 用：

```xml
<hostdev mode='subsystem' type='pci' managed='yes'>
  <source>
    <address domain='0x0000' bus='0x04' slot='0x10' function='0x0'/>
  </source>
</hostdev>
```

⚠️ 启用 SR-IOV **VF 不支持 live migration**（VF 绑死在某块网卡上）。

## 7. 性能对比

| 方案 | 吞吐 | PPS | 延迟 | 迁移 | 隔离 |
| --- | --- | --- | --- | --- | --- |
| user/NAT | ★★ | ★ | 高 | ✅ | ✅ |
| bridge | ★★★ | ★★ | 中 | ✅ | ✅ |
| vhost-net | ★★★★ | ★★★★ | 低 | ✅ | ✅ |
| macvtap | ★★★★ | ★★★★ | 低 | ✅ | ⚠️ |
| SR-IOV | ★★★★★ | ★★★★★ | 极低 | ❌ | ⚠️ |
| vhost-user | ★★★★★ | ★★★★★ | 极低 | ⚠️ | ⚠️ |

## 8. 防火墙 / NAT

libvirt 自带 nwfilter，可用 XML 写规则：

```xml
<interface type='bridge'>
  <source bridge='virbr0'/>
  <model type='virtio'/>
  <filterref filter='clean-traffic'>
    <parameter name='IP' value='192.168.122.10'/>
  </filterref>
</interface>
```

但生产更多直接用 iptables/nftables 或 OVS 规则。

## 9. 调试命令速查

```bash
# 宿主机
brctl show virbr0
ip link show type veth   # 所有 veth

# 抓包
tcpdump -i vnet0 -nn -e

# VM 内
ip -s link show eth0      # 看丢包
ethtool -S eth0           # 看队列统计
tc qdisc show dev eth0
```

## 10. 优劣对比速记

| 场景 | 推荐 |
| --- | --- |
| 本地开发 | user/NAT |
| 通用 VM | bridge + virtio |
| 高性能 VM | bridge + vhost-net + 多队列 |
| 极致性能 | SR-IOV 或 vhost-user + DPDK |
| 大规模云 | OVS-DPDK + VLAN/VXLAN |
| 边缘 / 隔离网络 | macvtap |

## 12. 小结

- 五种网络拓扑对应不同生产需求
- vhost-net 是性价比最高的「默认加速」
- 多队列把单核 virtio 变成多核并行
- SR-IOV / vhost-user 适合极致性能（但失去迁移能力）
- 调试从 `tcpdump -i vnet0` 开始
