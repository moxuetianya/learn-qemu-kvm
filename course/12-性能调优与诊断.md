# 12 · 性能调优与诊断

> 让 VM 跑得快且稳定。所有调优都该先测后调，否则就是瞎调。

## 学习目标

- 能用 perf / kvm_stat / ftrace 找瓶颈
- 知道 CPU 调度、内存、磁盘、网络分别怎么调
- 掌握常用基准工具（fio / iperf3 / unixbench / sysbench）
- 理解「观测 → 假设 → 实验 → 验证」的循环

## 1. 调优心法

```
   ┌────────────────┐
   │   1. 观测        │  perf / kvm_stat / sar / iostat
   └──────┬─────────┘
          ▼
   ┌────────────────┐
   │   2. 假设        │  「磁盘 IOPS 不够」「VM exit 太多」
   └──────┬─────────┘
          ▼
   ┌────────────────┐
   │   3. 实验        │  改一个参数，重测
   └──────┬─────────┘
          ▼
   ┌────────────────┐
   │   4. 验证        │  对比基线，决定取舍
   └────────────────┘
```

**不要盲目调优**。每改一个参数都做对照实验。

## 2. CPU 调优

### 2.1 vCPU 数 ≠ 越多越好

```bash
virsh setvcpus vm 8 --live --config
```

**经验值**：

| 负载类型 | vCPU |
| --- | --- |
| Web / 应用服务器 | 物理核数 / 2 |
| 数据库（CPU bound） | 物理核数 / 1.5 |
| 高并发 / 编译 | = 物理核数 |

### 2.2 CPU 绑定（pin）

详见 lab08。

```xml
<cputune>
  <vcpupin vcpu='0' cpuset='4'/>
  <vcpupin vcpu='1' cpuset='5'/>
  <emulatorpin cpuset='0-3'/>   <!-- 把 QEMU 线程隔开 -->
</cputune>
```

### 2.3 减少 VM exit

```bash
sudo kvm_stat
# 看哪种 exit_reason 最多
```

| 现象 | 优化 |
| --- | --- |
| I/O instruction 多 | virtio 替代全模拟 |
| EPT violation 多 | 配 hugepage |
| HLT 多 | 正常，无需管 |
| IRQ window 多 | 启用 APICv |
| CR access 多 | 检查内核是否虚拟化友好 |

### 2.4 kvm_stat 实战：读懂真实输出

`kvm_stat`（内核源码 `tools/kvm/kvm_stat/kvm_stat`）以 3 秒窗口显示增量：

```
Event                                         Total Current
 exits                                  41827392    62314     ← 每秒 exit 总量
 fpu_load (calls)                        1029312     1520
 halt_exits                              812345     1902     ← 空闲时的正常项
 halt_wakeup                             790111     1773
 ept_miss (gpa)                          512033     3401     ← 偏高 → hugepage
 invlpg_exits (exit_reason 14)           233401      981     ← 客户机刷 TLB 多
 io_exits (exit_reason 24)               190233       41     ← 低 → virtio 生效
 irq_exits (exit_reason 30)               98220      761
 cpuid_exits                             44101       130
 mmio_exits (exit_reason 49)              12203        6     ← 高 → 有全模拟设备
 msr_exits (exit_reason 31)               43221       590     ← 偏高 → 查 pv 驱动
```

读法（按当前列 Current 排序，单位是「次/采样窗口」）：

1. **先看 exits 总量**：除以窗口秒数得每秒 exit 数。
   轻负载 VM 每秒几千很正常；CPU 密集 + 高频定时器场景可能几十万。
2. **halt_exits 占大头** → VM 大部分时间空闲，是好事，不用管。
3. **ept_miss 偏高** → 内存压力信号，考虑 hugepage（3.1 节）。
4. **io_exits / mmio_exits 偏高** → 还有全模拟设备在热路径上，换 virtio。
5. **msr_exits / cpuid_exits 偏高** → 客户机内核没吃到 pv 优化
   （检查 `dmesg | grep -i kvm` 里是否有 `KVM setup paravirtual spinlocks` 等）。
6. **irq_exits 多** → 中断虚拟化没开好，看 APICv / posted-interrupt。

没有 kvm_stat 时用 perf 代替（信息等价）：

```bash
sudo perf stat -e kvm:kvm_exit -a -- sleep 5
sudo perf stat -e 'kvm:*exit' -a -- sleep 5   # 按原因细分
```

> `kvm_stat` 读的是 debugfs tracepoint，本身开销极小，可以常驻观察。

启用 APICv：

```xml
<features>
  <apic/>
</features>
<clock offset='localtime'>
  <timer name='rtc' tickpolicy='catchup'/>
  <timer name='pit' tickpolicy='delay'/>
  <timer name='hpet' present='no'/>
</clock>
```

### 2.4 启用 vhost

```xml
<interface type='bridge'>
  <source bridge='virbr0'/>
  <model type='virtio'/>
  <driver name='vhost' queues='4'/>
</interface>
```

## 3. 内存调优

### 3.1 hugepage

详见 lab08。

```bash
# host
sysctl -w vm.nr_hugepages=2048

# VM XML
<memoryBacking>
  <hugepages/>
  <locked/>
</memoryBacking>
```

效果：内存访问 TLB miss 减少，吞吐提升 5-15%。

### 3.2 内存合并（KSM）

```bash
echo 1 > /sys/kernel/mm/ksm/run
cat /sys/kernel/mm/ksm/pages_sharing
```

内核合并相同页。**风险**：在 NUMA 系统上可能拖慢。

### 3.3 balloon

```xml
<memballoon model='virtio'/>
```

适合内存超额分配。

### 3.4 内存 NUMA 亲和

```xml
<numatune>
  <memory mode='strict' nodeset='0'/>
</numatune>
```

VM 内存只在 node 0 分配，跨 node 访问延迟高。

## 4. 磁盘调优

### 4.1 cache 模式：先选对，再谈别的

QEMU 块层最重要的一个参数，直接决定性能和数据安全：

```
客户机 write ──► QEMU ──► 宿主机 page cache ──► 磁盘
                    │            │
                    └─ 何时算「写完成」？由 cache 模式决定
```

| cache= | 客户机写何时确认 | 宿主 O_DIRECT | 掉电风险 | 性能 | 适用 |
| --- | --- | --- | --- | --- | --- |
| `none` | 进 QEMU 就算（写穿到 host 发起） | ✅ | 低（靠盘的 FUA/flush） | 高 | **生产默认** |
| `writeback` | 进宿主 page cache 就算 | ❌ | 中（宿主崩溃丢最近写） | 最高 | 可容忍少量丢失 |
| `writethrough` | 同步写穿盘 | ❌ | 最低 | 低 | 数据极敏感 + 无 UPS |
| `directsync` | 同步写穿 + 直通 | ✅ | 最低 | 最低 | 同上 |
| `unsafe` | 完全不保证 | ❌ | 高 | 最高 | 临时 VM、安装镜像 |

```xml
<driver name='qemu' type='qcow2' cache='none' discard='unmap' detect_zeroes='unmap'/>
```

三个相关参数一起理解：

- `cache=none`：绕过宿主 page cache，客户机能自己管理缓存（推荐）。
  客户机里的 fsync 会原样传到物理盘（FUA），语义最正确。
- `discard=unmap`：客户机删文件 → 透传 TRIM → qcow2 瘦身 / SSD 回收块。
- `detect_zeroes=unmap`：写全零区域自动转 TRIM，镜像不虚胖。

> 常见翻车：`cache=unsafe` 装完系统忘记改回，迁移/快照后掉电丢数据。
> 建议除临时场景外一律 `cache=none`。

### 4.2 多队列 + iothread

```xml
<disk type='file' device='disk'>
  <driver name='qemu' type='qcow2' cache='none' io='native' queues='4' iothread='1'/>
  <source file='/var/lib/libvirt/images/vm.qcow2'/>
  <target dev='vda' bus='virtio'/>
</disk>
```

### 4.3 磁盘调度器（host）

```bash
cat /sys/block/nvme0n1/queue/scheduler
# [none] mq-deadline kyber bfq

echo none > /sys/block/nvme0n1/queue/scheduler   # 极致性能
echo mq-deadline > /sys/block/sda/queue/scheduler   # 默认
```

### 4.4 I/O 限速（QoS）

```xml
<disk type='file' device='disk'>
  <driver name='qemu' type='qcow2'/>
  <source file='/var/lib/libvirt/images/vm.qcow2'/>
  <target dev='vda' bus='virtio'/>
  <iotune>
    <read_bytes_sec>104857600</read_bytes_sec>
    <write_iops_sec>1000</write_iops_sec>
  </iotune>
</disk>
```

## 7. 性能基线

### 7.1 磁盘

```bash
# 顺序写
fio --name=seqwrite --filename=/dev/vda --rw=write \
    --bs=1M --size=1G --runtime=10 --time_based --direct=1 \
    --ioengine=libaio --iodepth=32

# 随机 4K
fio --name=randwrite --filename=/dev/vda --rw=randwrite \
    --bs=4k --size=1G --runtime=10 --time_based --direct=1 \
    --ioengine=libaio --iodepth=32

# 混合
fio --name=mixed --filename=/dev/vda --rw=randrw \
    --bs=4k --size=1G --runtime=10 --time_based --direct=1 \
    --rwmixread=70 --ioengine=libaio --iodepth=32
```

### 7.2 网络

```bash
# VM 内跑 iperf3 server
iperf3 -s

# host 跑 client
iperf3 -c 192.168.122.x -t 30 -P 4
```

## 8. 调优决策树

从「VM 慢」出发，按顺序排查，每步都有明确工具和动作：

```
VM 慢
 │
 ├─ 宿主机整体就慢？
 │   └─ sar -u / top：host %idle 低？
 │        ├─ 是 → 别调 VM，先解决宿主负载（或这台机器本来就超卖了）
 │        └─ 否 ↓
 │
 ├─ CPU 型慢（应用跑不动）？
 │   └─ VM 内 mpstat -P ALL 1：%iowait 低 + %sys 低 + %usr 高
 │        ├─ vCPU 不够 → 加 vCPU（但别超物理核，见 2.1）
 │        ├─ vCPU 争抢 → 宿主 pidstat -t 看 QEMU 线程 %wait → 绑核（lab08）
 │        └─ VM exit 太多 → kvm_stat（2.4）→ 按 exit_reason 对症
 │
 ├─ 磁盘型慢（iowait 高）？
 │   └─ VM 内 iostat -x 1：await 高 / util 100%
 │        ├─ cache 模式不对 → 改 none（4.1）
 │        ├─ 单队列打满 → queues=N + iothread（4.2）
 │        ├─ qcow2 元数据开销 → raw / preallocation=falloc
 │        └─ 后端盘本身就慢 → 宿主 iostat -x 1 看物理盘
 │
 ├─ 网络型慢（PPS/吞吐低）？
 │   └─ iperf3 基线（7.2）
 │        ├─ 吞吐低 → MTU 9000（5.2）、TCP 缓冲（5.3）
 │        ├─ PPS 低 → 多队列 + ethtool -L（5.1）、确认 vhost=on
 │        └─ 延迟抖 → 宿主软中断集中在 0 号核 → RPS/IRQ 亲和
 │
 └─ 延迟抖动（不慢但不稳）？
     ├─ CPU 频率漂移 → cpupower frequency-set -g performance
     ├─ NUMA 跨节点 → numastat -p qemu → numatune（3.4）
     ├─ 内存 ballooning 抖动 → 关 balloon 或固定内存
     └─邻居噪声 → 隔离核 isolcpus + 绑核（lab08）
```

> 每个叶子节点都是「一个可执行的命令 + 一个可验证的指标」。
> 调优最忌讳「感觉慢就加内存」——先让数据告诉你慢在哪一层。

## 9. 常见性能问题诊断

| 现象 | 检查 | 修复 |
| --- | --- | --- |
| 磁盘 IOPS 上不去 | `iostat` 看 %util | 加队列、改 IO 调度、换 SSD |
| 网络 PPS 不够 | `ethtool -S eth0` | vhost、多队列、巨帧 |
| CPU 跑不满 | `top` 看 %idle | 减 vCPU、绑核 |
| 延迟忽高忽低 | `perf` 看上下文切换 | 绑核、隔离核 |
| 启动慢 | – | cache=none 反而快 |
| 迁移时间太长 | 内存脏页速率 | auto-converge、限带宽 |

## 10. 案例：调优一个跑 MySQL 的 VM

### 9.1 基线

```
sysbench oltp_read_write --mysql-host=... --threads=64 run
# 假设 12,000 TPS
```

### 9.2 假设

- 磁盘 IOPS 是瓶颈（用 iostat 看 %util 接近 100%）

### 9.3 实验 1：多队列

```xml
<disk ... queues='4' iothread='1'/>
```

→ 14,000 TPS（+15%）

### 9.4 实验 2：hugepage

```xml
<memoryBacking><hugepages/></memoryBacking>
```

→ 14,800 TPS

### 9.5 实验 3：vhost-net

```xml
<interface ... <driver name='vhost' queues='4'/></interface>
```

→ 15,200 TPS（网络是次瓶颈）

### 9.6 收工

TPS 12k → 15.2k，CPU 占用降低。
