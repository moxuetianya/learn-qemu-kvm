# 01 · 虚拟化基础理论

> 本章是后面所有章节的「地基」。理论不深，5 分钟读完，但要常回来翻。

## 学习目标

读完本章，能用自己的话讲清楚：

- 什么是虚拟化、为什么需要
- 「全虚拟化」「半虚拟化」「硬件辅助虚拟化」的区别与权衡
- KVM 属于哪一种
- 虚拟化的三大子问题：CPU / 内存 / I/O

## 1. 什么是虚拟化

虚拟化 = **「用软件模拟硬件，让一台物理机跑出多台逻辑独立的机器」**。

更工程化的定义：

> 虚拟化是对资源（CPU、内存、I/O、网络）的逻辑抽象、隔离、再分配和管理的过程。

注意「隔离」是关键词——它保证一台 VM 出问题不会影响别的 VM，也不会穿透到宿主机。

### 为什么要做

1. **提升资源利用率**：传统服务器 CPU 利用率 5-15%，虚拟化后可整合到 60%+
2. **隔离**：多租户环境刚需
3. **可迁移**：VM 是文件，物理机坏了换一台接着跑
4. **快速交付**：从镜像启动一台 VM 比装机快 100 倍

### 一个反直觉的事实

虚拟化本质上是「**大型机思维**」的回归。1960 年代 IBM 大型机本来就这么干，x86 时代又被 VMware 拿回来。原因简单：**钱**。

## 2. 三种核心分类（生产用得到）

### 按实现方式

| 类型 | 原理 | 例子 | 优劣 |
| --- | --- | --- | --- |
| **全虚拟化（Full）** | 客户机不知道自己被虚拟化，VMM 截获所有敏感指令 | VMware Workstation（早期）、KVM+QEMU | ✅ 兼容性最好（OS 不需改）<br>⚠️ 早期纯软件实现有性能损耗 |
| **半虚拟化（Para）** | 客户机**知道**自己被虚拟化，主动调用 hypercall | Xen（PV 模式）、virtio | ✅ 性能高<br>⚠️ 客户机 OS / 驱动要改（Windows 早期不支持） |
| **硬件辅助虚拟化（HVM）** | CPU 硬件支持根模式 / 非根模式，敏感指令硬件截获 | Intel VT-x、AMD-V | ✅ 性能接近原生 + 兼容性好<br>⚠️ 依赖 CPU |

> **生产怎么选？**
> - 服务器虚拟化（OpenStack、oVirt、Proxmox）几乎全部走「**硬件辅助 + virtio 半虚拟化设备**」组合。
> - 早期 Xen 因为 ARM 架构生态分裂，又用回 PV，性能反而更好。
> - 你很少会遇到纯软件全虚拟化（QEMU TCG 模式只用于跨架构仿真）。

### 按架构位置

| 类型 | 例子 | 优劣 |
| --- | --- | --- |
| **Type-1（裸金属）** | VMware ESXi、Xen（直接跑在硬件上） | ✅ 性能好，Hypervisor 体积小<br>⚠️ 驱动要自己解决 |
| **Type-2（宿主）** | QEMU/VMware Workstation（跑在普通 OS 上） | ✅ 部署简单<br>⚠️ 多一层 OS 开销 |
| **混合** | KVM（Linux 内核本身就是 Hypervisor，QEMU 跑在它上面） | ✅ 利用 Linux 驱动栈<br>⚠️ 内核挂了 = 所有 VM 挂 |

**KVM 是混合模型**——这点很重要，意味着所有 Linux 内核能力（cgroup、namespace、selinux、netfilter…）天然能给 VM 用。

## 3. 虚拟化的三大子问题

> 「**只要 CPU 虚拟化解决，其他都好办**」——这是经典结论。

### 3.1 CPU 虚拟化

目标：让多个 VM 共享物理 CPU，每个 VM 都以为独占。

问题：x86 有 17 条「敏感指令」（如 `lgdt`、`hlt`、访问控制寄存器），这些指令无法在用户态 trap。

**三种解法**：

1. **二进制翻译（BT）**：VMware 早期方案，把敏感指令替换成跳转
2. **半虚拟化**：直接修改客户机 OS，避免执行敏感指令
3. **硬件辅助（VMX/SVM）**：CPU 加一层「根模式」，敏感指令由硬件触发 VM exit

**KVM 走第三种**——这也是 KVM 性能好的根本原因。

### 3.2 内存虚拟化

目标：让每个 VM 拥有独立的、连续的、从 0 开始的物理地址空间。

**两阶段地址翻译**：

```
客户机虚拟地址 (GVA)
   │  ① 客户机页表
   ▼
客户机物理地址 (GPA)
   │  ② EPT/NPT 页表（由 VMM 维护）
   ▼
宿主机物理地址 (HPA)
```

**影子页表**（早期方案）：VMM 监听 `mov cr3`，把客户机页表复制成一份「影子」——复杂、性能差。

**EPT（Intel）/ NPT（AMD）**：硬件直接做两阶段翻译，VMM 只填表——性能高，是生产方案。

### 3.3 I/O 虚拟化

目标：让 VM 访问「虚拟设备」（虚拟磁盘、网卡、显卡）。

**三种方式**：

| 方式 | 原理 | 性能 | 兼容性 |
| --- | --- | --- | --- |
| **全模拟** | VMM 模拟一个完整设备（如 e1000、IDE） | ❌ 差 | ✅ 好（任何 OS 都带驱动） |
| **半虚拟化（virtio）** | VM 里装特殊驱动，前后端共享环形缓冲区 | ✅ 接近原生 | ⚠️ OS 需要 `virtio-*` 内核模块（Linux 早就有） |
| **设备直通（PCI-passthrough / SR-IOV）** | 把物理设备直接给 VM | ✅✅ 接近原生 | ⚠️ 主板 / BIOS / 内核都得支持 IOMMU |

> **生产怎么选？**
> - 普通 VM：virtio 块 / 网，性能/兼容性平衡最好
> - 高性能场景（数据库、高频交易）：PCI 直通或 SR-IOV
> - 调试场景：全模拟，省事

## 4. 关键模型对比：KVM 在哪一格

| 维度 | KVM |
| --- | --- |
| 模型 | Type-1 混合（Linux 内核 + QEMU） |
| CPU 虚拟化 | 硬件辅助（VMX/SVM） |
| 内存虚拟化 | EPT / NPT |
| I/O 虚拟化 | virtio（默认）/ 直通 / 全模拟 |
| 调度 | Linux CFS |
| 隔离 | Linux 进程 + cgroup + namespace + sVirt |
| 客户机 | 任意 OS（含 Windows、BSD） |

## 5. 一个心智模型

把 QEMU/KVM 想成一个三层结构：

```
┌─────────────────────────────────────────────┐
│  Guest OS（Windows / Linux）                  │ ← 客户机：以为独占硬件
├─────────────────────────────────────────────┤
│  QEMU（用户态进程）                            │ ← 模拟外设 + 提供管理面
├─────────────────────────────────────────────┤
│  KVM 内核模块 + /dev/kvm + virtio 后端         │ ← 真正跑 CPU/内存虚拟化
├─────────────────────────────────────────────┤
│  Linux 内核（调度 / 内存 / 网络 / 驱动）        │ ← 利用整颗内核能力
├─────────────────────────────────────────────┤
│  硬件（Intel VT-x / EPT / IOMMU）              │
└─────────────────────────────────────────────┘
```

记住这张图，后面所有章节都往里填东西。

## 6. 优劣对比速记

| 场景 | 推荐方案 | 不推荐方案 |
| --- | --- | --- |
| 普通服务器虚拟化 | KVM + virtio + EPT | – |
| 高 I/O 吞吐（数据库） | SR-IOV / NVMe 直通 | 全模拟 IDE |
| 跨架构开发（嵌入式仿真） | QEMU TCG（纯软件） | – |
| 容器化部署 | KubeVirt（KVM + k8s） | – |
| 桌面上跑别的 OS | QEMU HVF / WHPX | – |

## 7. 小结

- **虚拟化 = 拦截 + 重定向**
- **CPU 虚拟化**：硬件辅助（VMX/SVM）已成绝对主流
- **内存虚拟化**：EPT/NPT 解决了「两阶段翻译」
- **I/O 虚拟化**：virtio 是兼容性 + 性能的最佳平衡
- **KVM = 借 Linux 内核能力的 Type-1**

## 8. 思考题
