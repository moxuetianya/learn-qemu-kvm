# 10 · 图形与显示方案对比

> VM 「画面」怎么呈现给用户，是 VNC？SPICE？还是 GPU 直通？

## 学习目标

- 能区分 VNC / SPICE / virtio-gpu 的能力
- 知道 SPICE 为何适合桌面虚拟化
- 理解 GPU 直通与 vGPU 的取舍
- 能在生产场景里选对方案

## 1. 全景

```
┌─────────────────────────────────────┐
│  客户机 OS                            │
│  显卡驱动（QXL / VGA / virtio-gpu）   │
└─────────────────┬───────────────────┘
                  │ 帧数据
┌─────────────────▼───────────────────┐
│  QEMU / vhost-user-gpu               │
│  后端：画 frame → 编码 → 协议         │
└─────────────────┬───────────────────┘
                  │ 网络协议（VNC/RDP/SPICE）
┌─────────────────▼───────────────────┐
│  客户端（VNC viewer / remote-viewer）  │
└─────────────────────────────────────┘
```

## 2. 三种主流方案

### 2.1 VNC

- 协议：RFB（Remote Frame Buffer）
- 编码：raw / ZRLE / Tight
- 特点：**最简单、几乎通用**

```bash
-vnc :0                    # 5900
-vnc 127.0.0.1:0,password  # 加密码
```

**优势**：
- 几乎所有设备都有 VNC 客户端
- 实现简单，调试友好

**劣势**：
- 不支持视频流加速（每帧重传）
- 单连接，不能多端同时看

### 2.2 SPICE

- 协议：开源的 SPICE 协议
- 编码：图像变化推送、quic、mjpeg
- 特点：**为桌面虚拟化设计**

```bash
-spice port=5900,addr=127.0.0.1,password=xxx,disable-ticketing=on
```

**优势**：
- 视频流（spice-vdagent 后，4K 视频流畅）
- 多端连接（多人同时看）
- USB 重定向
- 双向剪贴板、文件拖拽

**劣势**：
- 客户端主要是 remote-viewer（virt-viewer）
- 实现复杂度高

### 2.3 RDP（微软）

不是 QEMU 原生支持，得借助 XRDP / VNC-RDP 网关。

### 2.4 virtio-gpu

不算「远程显示协议」，而是「GPU 模拟器」。

| 模式 | 用途 |
| --- | --- |
| 无 virgl | 2D 加速 |
| virgl | 3D 加速（OpenGL 4.x） |
| venus | Vulkan（实验） |

```xml
<video>
  <model type='virtio' heads='1' virgl='on'/>
</video>
```

**优势**：3D 性能接近原生
**劣势**：需要 Linux 5.x+，Windows 客户端少

## 3. 对比矩阵

| 维度 | VNC | SPICE | virtio-gpu | GPU 直通 |
| --- | --- | --- | --- | --- |
| 2D 性能 | ★★★ | ★★★★ | ★★★★ | ★★★★★ |
| 3D 性能 | ❌ | ★ | ★★★★ | ★★★★★ |
| 视频流畅 | ❌ | ✅✅ | ✅ | ✅✅✅ |
| 多端同看 | ❌ | ✅ | ❌ | ❌ |
| USB 重定向 | ❌ | ✅ | ❌ | ✅ |
| 剪贴板 | ❌ | ✅ | ❌ | ✅ |
| 网络依赖 | 低 | 中 | – | – |
| 调试便利 | ★★★★★ | ★★★ | ★★★ | ★ |

## 4. 各方案适用场景

| 场景 | 推荐 |
| --- | --- |
| 服务器维护（无 GUI） | VNC |
| 普通办公桌面 | SPICE |
| 远程工作站 / 设计 | GPU 直通 + SPICE |
| AI 训练 / CUDA | GPU 直通 + RDP |
| 游戏云 | GPU 直通或 vGPU |
| 大屏展示 | SPICE |

## 5. SPICE 进阶

### 5.1 启用 vdagent

客户机装 spice-vdagentd：

```sh
apk add spice-vdagent  # Alpine
apt install spice-vdagent  # Debian/Ubuntu
```

效果：

- 客户机分辨率自适应客户端窗口
- 剪贴板共享
- USB 重定向（需要客户端支持）

### 5.2 多端连接

```bash
# QEMU 启动
-spice port=5900,password=xxx
# 多个 client 连同一端口，可同时看
```

### 5.3 TLS 加密

```bash
-spice port=5901,tls-port=5901,\
      x509-dir=/etc/pki/libvirt-spice,\
      tls-channel=main,plaintext-channel=input
```

## 6. GPU 直通实战

### 6.1 硬条件

- 主板 BIOS 打开 VT-d / IOMMU
- GPU 在独立 IOMMU group
- 足够大页（建议 1GB hugepage）

### 6.2 步骤

```bash
# 主机绑定 vfio-pci
echo "vfio-pci" > /sys/bus/pci/devices/0000:01:00.0/driver_override
echo "0000:01:00.0" > /sys/bus/pci/drivers/vfio-pci/bind

# 启动 VM
qemu-system-x86_64 \
    -machine q35,accel=kvm \
    -cpu host,kvm=on,vendor=GenuineIntel \
    -m 16G -smp 8 \
    -drive file=vm.qcow2,format=qcow2,if=virtio \
    -device vfio-pci,host=01:00.0,x-pci-vendor-id=0x10de,x-pci-device-id=0x1c03 \
    -vga none \
    -display none \
    -spice port=5900,password=xxx
```

### 6.3 性能

| 应用 | 直通前 | 直通后 |
| --- | --- | --- |
| CUDA 训练 | 不可用 | 95% 原生 |
| 4K 视频播放 | 30fps | 60fps |
| OpenGL 4.x | ❌ | ✅✅ |

## 7. SR-IOV 与 vGPU

### 7.1 NVIDIA vGPU

把一张数据中心 GPU（如 A40）分成多个 vGPU（如 1q / 2q / 4q），每个 VM 用一份。

优点：
- 多个 VM 共享 GPU
- 帧缓冲隔离
- 接近原生性能

缺点：
- License 贵
- 受支持的 GPU 型号少

### 7.2 SR-IOV for NIC

详见 08 章。

```bash
# 客户机内
# 看 GPU 利用率（直通过后）
nvidia-smi

```

## 9. 优劣对比速记

| 需求 | 推荐 |
| --- | --- |
| 远程桌面 | SPICE + vdagent |
| 视频播放 | GPU 直通 |
| AI / CUDA | GPU 直通 |
| 移动办公 | SPICE |
| 服务端（无 GUI） | VNC |

## 10. 小结

- **VNC** = 简单通用
- **SPICE** = 桌面虚拟化首选（需要 vdagent）
- **virtio-gpu** = 虚拟化里的 3D 加速
- **GPU 直通** = 极致性能，需要硬件 + 操作系统支持
