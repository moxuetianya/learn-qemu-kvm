# 07 · 存储虚拟化详解

> 客户机「看到的」磁盘是「真」的，但实际是宿主机的镜像文件、lun、网络磁盘……

## 学习目标

- 区分各种镜像格式的优劣
- 知道 virtio-blk、virtio-scsi 的差异
- 理解 backing file、快照、copy-on-write
- 知道生产环境共享存储怎么做

## 1. 存储栈全景

```
客户机 OS（ext4 / NTFS / XFS）
     │
     │ virtio-blk / virtio-scsi / IDE / SATA / NVMe（前端）
     ▼
QEMU 后端（virtio 控制器）
     │
     │ 块设备 / 文件 / NBD / iSCSI / Ceph RBD
     ▼
宿主机内核（page cache / AIO）
     │
     ▼
物理磁盘 / SSD / NVMe / 远端存储
```

## 2. 镜像格式对比

| 格式 | 性能 | 快照 | 加密 | 压缩 | 兼容 | 适用 |
| --- | --- | --- | --- | --- | --- | --- |
| **raw** | ★★★★★ | ❌ | ❌ | ❌ | ✅ 任何 | 数据库、高性能 |
| **qcow2** | ★★★★ | ✅ 内部 | ✅ | ✅ | QEMU/KVM | 通用 |
| **vmdk** | ★★★★ | ✅ | ❌ | ❌ | VMware | 跨平台 |
| **vdi** | ★★★★ | ✅ | ❌ | ❌ | VBox | VBox |
| **qed** | ★★★★ | ✅ | ❌ | ❌ | QEMU | 已废弃 |

### raw vs qcow2 性能对比（典型）

| 操作 | raw | qcow2 | 差距 |
| --- | --- | --- | --- |
| 顺序读 | 100% | 90-95% | 5-10% |
| 随机写 4K | 100% | 70-85% | 15-30% |
| snapshot 创建 | N/A | O(1) | qcow2 赢 |
| 复制迁移 | O(size) | O(实际占用) | qcow2 赢 |

## 3. qcow2 高级特性

### 3.1 内部快照 vs 外部快照

```bash
# 内部快照：所有数据存在同一个 qcow2
qemu-img snapshot -c snap1 lab03.qcow2

# 外部快照：base 不变，创建一个 delta
qemu-img snapshot -c snap1 lab03.qcow2
# 等价于：
qemu-img rebase -b lab03.qcow2 snap1.qcow2
```

**生产推荐外部快照**——可以分层、可以独立分发。

### 3.2 backing file（差分镜像）

```bash
# 共享一个 base，多个 VM 各一个 delta
qemu-img create -f qcow2 \
    -b /var/lib/libvirt/images/ubuntu-base.qcow2 \
    -F qcow2 /var/lib/libvirt/images/ubuntu-vm1.qcow2
```

10 个 VM 共享一个 base，节省 90% 磁盘（取决于 OS 复用率）。

### 3.3 预分配

```bash
# metadata：立即分配元数据
qemu-img create -f qcow2 -o preallocation=metadata test.qcow2 10G

# falloc：立即占空间（推荐数据库）
qemu-img create -f qcow2 -o preallocation=falloc test.qcow2 10G

# full：与 raw 等价
qemu-img create -f qcow2 -o preallocation=full test.qcow2 10G
```

### 3.4 加密

```bash
qemu-img create -f qcow2 -o encryption=on secret.qcow2 10G
# 加密密钥在 qemu 启动时通过 qemu-img info 或密钥文件提供
```

## 4. 设备类型对比

### 4.1 控制器层

| 控制器 | 吞吐 | IOPS | 特性 | 推荐 |
| --- | --- | --- | --- | --- |
| IDE | 差 | 差 | 兼容性最好 | 老 OS |
| SATA | 中 | 中 | NCQ、TRIM | 老 OS |
| **virtio-blk** | 优 | 优 | 单队列，≤1K IOPS | 单队列高吞吐 |
| **virtio-scsi** | 优 | 优 | 多队列、SCSI 命令全 | **多盘场景** |
| **NVMe** | 优 | 优 | NVMe 模拟 | 直通场景 |

### 4.2 virtio-blk vs virtio-scsi

| 维度 | virtio-blk | virtio-scsi |
| --- | --- | --- |
| 单队列 | ✅（多队列版本 v1.1+） | ✅（多队列） |
| SCSI 命令 | ❌ | ✅（UNMAP、PR 等） |
| 热插 | 难 | ✅ |
| 多盘共享控制器 | ❌ | ✅ |
| 性能 | 高 | 高 |

**生产推荐**：单盘用 virtio-blk；多盘、SCSI 设备用 virtio-scsi。

### 4.3 队列优化

```xml
<disk type='file' device='disk'>
  <driver name='qemu' type='qcow2' queues='4'/>
  <source file='/var/lib/libvirt/images/lab03.qcow2'/>
  <target dev='vda' bus='virtio'/>
</disk>
```

> `queues=N`：每个 vCPU 一个队列。多 vCPU 配多队列性能明显。

VM 内确认：

```sh
ls /sys/block/vda/mq/
# 0 1 2 3
cat /sys/block/vda/queue/nr_requests
```

## 5. I/O 模式

### 5.1 native（AIO）

```xml
<disk type='file' device='disk'>
  <driver name='qemu' type='qcow2' io='native'/>
</disk>
```

走 Linux kernel AIO（`O_DIRECT`）。**生产默认**。

### 5.2 threads

```xml
<driver name='qemu' type='qcow2' io='threads'/>
```

QEMU 单独起线程处理 I/O。性能差，但兼容性最好。

### 5.3 缓存策略

| cache | 含义 | 性能 | 风险 |
| --- | --- | --- | --- |
| `none` | 不缓存（最常用） | 高 | 客户机脏写穿透 |
| `writethrough` | 写穿透宿主机页缓存 | 中 | 写慢 |
| `writeback` | 写回（QEMU 层缓存） | 高 | 崩溃丢数据 |
| `directsync` | O_SYNC 写 | 慢 | 最安全 |
| `unsafe` | 跳过屏障 | 最高 | 崩溃可能丢数据 |

**生产推荐**：`cache=none` + 文件系统 `O_DIRECT`。

## 6. 共享存储方案

### 6.1 NFS

```bash
# server
echo '/srv/kvm 192.168.122.0/24(rw,sync,no_subtree_check)' \
    >> /etc/exports

# client (libvirt 启动时)
<disk type='file' device='disk'>
  <driver name='qemu' type='qcow2' cache='none'/>
  <source file='/mnt/nfs/lab03.qcow2'/>
  <target dev='vda' bus='virtio'/>
</disk>
```

> ⚠️ NFS 文件锁可能跟 live migration 冲突，记得加 `<source ... shareable='yes'/>`。

### 6.2 iSCSI

```bash
# server：targetcli
targetcli backstores/fileio create lab03 /srv/kvm/lab03.img 4G
targetcli iscsi/ create iqn.2026-09.com.example:lab03
targetcli iscsi/iqn.2026-09.com.example:lab03/tpg1/luns create /backstores/fileio/lab03
targetcli saveconfig
systemctl enable --now target

# client
iscsiadm -m discovery -t sendtargets -p 192.168.122.10
iscsiadm -m node -L all
# /dev/sdX 出现
```

VM 直接用 `/dev/sda` 作为 raw 设备：

```xml
<disk type='block' device='disk'>
  <driver name='qemu' type='raw' io='native'/>
  <source dev='/dev/disk/by-path/...'/>
  <target dev='sda' bus='scsi'/>
</disk>
```

### 6.3 Ceph RBD

```xml
<disk type='network' device='disk'>
  <driver name='qemu' type='raw'/>
  <source protocol='rbd' name='pool/lab03'>
    <host name='192.168.122.10' port='6789'/>
  </source>
  <auth username='libvirt'>
    <secret type='ceph' usage='pool'/>
  </auth>
  <target dev='vda' bus='virtio'/>
</disk>
```

✅ **云时代标配**：副本、克隆、快照原生支持。

### 6.4 NVMe-oF

更高性能，详见 `man nvme-cli`。

## 7. I/O 性能调优 checklist

```bash
# 1. 用 cache='none' + io='native'
# 2. 配多队列 queues=N
# 3. 大块顺序写：blk_mq 多队列 + 大块 (256k)
# 4. 镜像放 NVMe，不要放机械盘
# 5. 不要开 qemu-guest-agent 之外的额外 agent
# 6. 客户机文件系统用 xfs/ext4 + noatime
# 7. 数据库场景考虑 iothread 隔离
```

### iothread 隔离

```xml
<iothreads>2</iothreads>
<disk ...>
  <driver iothread='1'/>
  <target dev='vda' bus='virtio'/>
</disk>
```

效果：I/O 线程绑到专属 vCPU，避免跟主线程争 CPU。

## 8. 优劣对比速记

| 场景 | 推荐方案 |
| --- | --- |
| 单台数据库 VM | raw + iothread + NVMe 透传 |
| 通用 VM | qcow2 + cache=none + virtio-scsi 多队列 |
| 模板分发 | qcow2 + backing file |
| 多 VM 共享 OS | qcow2 backing |
| 大规模云 | Ceph RBD |
| 跨集群迁移 | 共享 NFS / Ceph |

## 10. 小结

- qcow2 是 QEMU/KVM 事实标准；raw 在极致性能场景用
- 设备推荐：virtio-blk 或 virtio-scsi 多队列
- 缓存策略生产用 `cache=none + io=native`
- 共享存储：NFS（简单） / iSCSI（块） / Ceph（云）
