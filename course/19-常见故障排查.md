# 19 · 常见故障排查

> 90% 的 KVM 问题有已知答案。这章把常见故障 + 排查思路 + 解法列出来。

## 学习目标

- 能用 `dmesg` / `journalctl` / `virsh` / `qemu-monitor` 排错
- 掌握常见故障的「症状 → 诊断 → 修复」三段式
- 知道何时看 `kvm_stat` / `perf` / `strace`

## 1. 排查顺序心法

```
   ┌─────────────────┐
   │ 1. 现象          │  VM 起不来？卡？性能差？
   └──────┬──────────┘
          ▼
   ┌─────────────────┐
   │ 2. 第一刀：日志   │  dmesg / journalctl / VM 内 console
   └──────┬──────────┘
          ▼
   ┌─────────────────┐
   │ 3. 隔离        │  宿主机 OK 吗？KVM 模块？网络？存储？
   └──────┬──────────┘
          ▼
   ┌─────────────────┐
   │ 4. 工具定位     │  strace / ltrace / bpftrace
   └──────┬──────────┘
          ▼
   ┌─────────────────┐
   │ 5. 修复 + 验证   │  改配置、重跑、观察
   └─────────────────┘
```

## 2. 启动失败

### 2.1 `error: Failed to start domain ...`

```bash
journalctl -xeu libvirtd --no-pager | tail -50
```

常见：

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `unsupported configuration` | CPU 不支持某特性 | 改 CPU model |
| `monitor socket ... failed` | socket 占用 | `rm` socket |
| `qemu-kvm: cannot set up guest memory` | host 内存不够 | 加内存 / 减 VM |
| `failed to find /usr/share/qemu/OVMF.fd` | 没装 OVMF | `apt install ovmf` |
| `permission denied on /dev/kvm` | 用户没权限 | `usermod -aG kvm $USER` |

### 2.2 VM 起得来但 `virsh list` 显示 shut off

```bash
virsh dominfo vm
virsh console vm
# 多数情况：guest 引导失败 → OS 装坏 / 内核参数错
```

VM 引导流程卡哪：

```bash
# 看 console 输出（XML 里配 console）
virsh console vm
# 看到 grub → 内核启动失败
# 看到空白 → 磁盘读不出来
```

## 3. 性能差

### 3.1 总体慢

```bash
# host
top
iostat -x 1
sar -n DEV 1

# VM 内
top
iostat -x 1   # apt install sysstat
mpstat -P ALL 1
```

### 3.2 VM exit 太多

```bash
sudo kvm_stat
```

| 现象 | 处理 |
| --- | --- |
| `io` 多 | 检查 virtio 驱动、qemu-guest-agent |
| `mmio` 多 | 同上 |
| `cpuid` 太多 | 异常，看是否客户机在循环 |
| `cr_access` 多 | 客户机内核频繁切换 CR，hugepage 缓解 |
| `halt` 多 | 正常，CPU 空闲 |

### 3.3 延迟抖动

```bash
# host
sudo cyclictest -p 99 -t 5 -n -D 1h -m -i 1000 -h 200 -q
# 测调度延迟

# VM 内
sudo cyclictest -p 99 -t 5 -n -D 1h
```

| 抖动来源 | 解决 |
| --- | --- |
| 宿主机 swap | 关闭 swap 或控制 vm.swappiness |
| 电源管理 C-state | `intel_idle.max_cstate=0` |
| 透明大页 | `echo never > /sys/kernel/mm/transparent_hugepage/enabled` |
| 调度器 | 用 isolcpu + cpuset 隔离核 |
| 中断亲和 | `IRQBALANCE_BANNED_CPUS` |

## 4. 网络问题

### 4.1 VM 拿不到 IP

```bash
# 1. host 看 DHCP 分配
virsh net-dhcp-leases default

# 2. 看 VM 内 dhclient 日志
journalctl -u dhclient -u systemd-networkd

# 3. 抓包
sudo tcpdump -i virbr0 -nn -e
```

### 4.2 VM 上不了外网

```bash
# host
sudo iptables -t nat -L -n -v
sudo sysctl net.ipv4.ip_forward
# 期望 = 1
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward
```

### 4.3 桥接不通

```bash
# 物理网卡没加入桥
brctl show br0

# STP 阻塞
brctl showstp br0
```

## 5. 存储问题

### 5.1 磁盘 IO 错误

```bash
# host
dmesg | grep -i -e ata -e nvme -e sd

# 看镜像
qemu-img check /var/lib/libvirt/images/vm.qcow2
qemu-img info /var/lib/libvirt/images/vm.qcow2
qemu-img amend -f qcow2 -o compat=1.1 /var/lib/libvirt/images/vm.qcow2
```

### 5.2 共享盘损坏

```bash
# 多个 VM 同时写同一个 backing file
qemu-img info vm.qcow2
# 看 backing file 指向

# 防止再写：libvirt XML 加 <shareable/>
```

### 5.3 文件锁

```bash
# VM 异常退出后盘被锁
ls -la /var/lib/libvirt/images/
# 有 .lock 文件
rm /var/lib/libvirt/images/vm.qcow2.lock  # 先确认 VM 没在跑
```

## 6. 迁移失败

### 6.1 `unknown OS`

```bash
# 两边 libvirt 版本不一致
virsh --version
# 升到一致
```

### 6.2 卡在 N%

```bash
# 看迁移进度
virsh domjobinfo vm --completed
```

| 字段 | 含义 |
| --- | --- |
| `dataProcessed` | 已传输字节 |
| `dataRemaining` | 剩余 |
| `memIteration` | 第几轮 |

如果 `dataRemaining` 不下降：脏页速率超过带宽。

### 6.3 `Operation not supported: migration`

```bash
# 共享盘问题
virsh edit vm
# 加 <shareable/>
```

## 7. 客户机无响应

```bash
# 1. 强制重启
virsh reset vm

# 2. 看内核输出
virsh console vm
# 或者
virsh domblklist vm
# 看 console=pty 拿 stdout

# 3. kdump
# 在客户机内核加 crashkernel=256M
# 触发 panic，看 /var/crash

# 4. 抓 perf 数据
virsh perf vm --list
```

## 8. 安全相关

### 8.1 sVirt 拒绝访问

```bash
# 看 SELinux 拒绝
sudo ausearch -m avc --comm qemu-system-x86 | tail -30

# 临时放行
sudo ausearch -m avc -ts recent | audit2allow -M myqemu
sudo semodule -i myqemu.pp
```

### 8.2 VM 逃逸 CVE

```bash
qemu-system-x86_64 --version
# 升到最新
sudo apt update && sudo apt upgrade qemu-*

# 关注 https://www.qemu.org/security/
```

## 9. 工具清单

### 9.1 主机

| 工具 | 场景 |
| --- | --- |
| `dmesg` | 内核日志 |
| `journalctl -u libvirtd` | libvirtd 日志 |
| `virsh dominfo vm` | VM 配置 |
| `virsh domstate vm` | VM 当前状态 |
| `virsh domjobinfo vm` | 迁移任务 |
| `virsh dump vm /tmp/dump` | 客户机内存 dump |
| `qemu-img check` | 镜像检查 |
| `qemu-img rebase` | 修复 backing chain |
| `kvm_stat` | VM exit 统计 |
| `perf top -e kvm:*` | KVM 子系统热点 |
| `bpftrace -e 'kprobe:kvm_vmx_handle_exit {...}'` | 自定义探针 |

### 9.2 客户机

| 工具 | 场景 |
| --- | --- |
| `journalctl -b` | 启动日志 |
| `dmesg` | 内核日志 |
| `mpstat -P ALL 1` | 每核 CPU |
| `iostat -x 1` | 磁盘 IO |
| `sar -n DEV 1` | 网络 |
| `strace -p PID` | 进程系统调用 |
| `perf record -g -p PID` | 进程热点 |

## 10. 实战排错剧本

### 剧本 1：VM 启动报 "internal error"

```bash
# 1. 看日志
journalctl -xeu libvirtd | tail -30

# 2. 看到 "kvm: ... Device or resource busy"
lsmod | grep kvm
# 可能 kvm_intel/kvm_amd 互相冲突（Intel 平台卸载 kvm_amd）

# 3. 看到 "monitor socket already in use"
rm /tmp/vm-monitor.sock

# 4. 看到 "Permission denied /dev/kvm"
ls -la /dev/kvm
sudo chmod 666 /dev/kvm  # 临时
sudo usermod -aG kvm $USER  # 持久
```

### 剧本 2：VM 性能差

```bash
# 1. host 看 CPU
top  # qemu 进程 CPU 跑满

# 2. kvm_stat 看 exit reason
sudo kvm_stat
# EPT misconfig 多 → 检查 hugepage
# IO 多 → 检查 virtio
# halt 多 → 正常

# 3. perf 跟 QEMU
sudo perf top -p $(pidof qemu-system-x86_64)

# 4. VM 内看
mpstat -P ALL 1
iostat -x 1
```

### 剧本 3：迁移卡死

```bash
# 1. 看迁移状态
virsh domjobinfo vm
# memIteration: 50  ← 第 50 轮还没完
# dataRemaining: 1G  ← 还有 1G 脏页

# 2. 取消
virsh domjobabort vm

# 3. 改带宽 + auto-converge 重试
virsh migrate --live vm \
    --desturi qemu+ssh://host2/system \
    --bandwidth 200 --auto-converge
```

## 11. 速查速记

| 现象 | 第一反应 |
| --- | --- |
| VM 起不来 | `journalctl -xeu libvirtd` |
| VM 启动卡 | `virsh console vm` |
| 性能差 | `kvm_stat` + `top` |
| 网络断 | `tcpdump -i virbr0` |
| 磁盘坏 | `qemu-img check` |
| 迁移失败 | `virsh domjobinfo` |
| 怀疑逃逸 | 升级 QEMU + 关 9p |
| 调度抖动 | `cyclictest` + `isolcpu` |

## 12. 小结

- 日志是第一刀
- `virsh console` + `kvm_stat` + `tcpdump` + `qemu-img` 是四件套
- 隔离：先把 host 排除，再查 VM
- 工具选型：粗看 `kvm_stat`，细看 `perf`/`bpftrace`
