# 14 · 安全与隔离

> KVM 本身提供了强隔离，但「攻击面」并没有消失。生产要做的事情比想象的多。

## 学习目标

- 理解 VM 的安全边界
- 能用 sVirt + cgroup + namespace 强化隔离
- 知道常见 VM 逃逸攻击路径
- 知道磁盘、网络、控制面的安全策略

## 1. 威胁模型

```
   ┌──────────────────────────────────┐
   │            客户机 A                │
   │ 攻击者控制客户机 OS                │
   │ 想：拿宿主机 / 其他 VM             │
   └──────────────────┬───────────────┘
                      │ 边界
   ┌──────────────────▼───────────────┐
   │            宿主机                 │
   │  内核 + QEMU + libvirtd           │
   └──────────────────┬───────────────┘
                      │ 边界
   ┌──────────────────▼───────────────┐
   │        控制面 / API / 网络         │
   │ 攻击者：远程入侵 libvirt / API     │
   └──────────────────────────────────┘
```

三层威胁：

1. **VM 内 → VM 逃逸**：客户机 OS 提权 → 跳出 VM
2. **VM 内 → 邻居 VM**：越界访问其他 VM 内存 / 磁盘
3. **外部 → 控制面**：拿到 libvirt API → 操控所有 VM

## 2. VM 逃逸防御

### 2.1 严格 I/O 模拟

QEMU 默认是「用户态进程」，理论上所有 CVE 都可能影响宿主。保持 QEMU 新版本：

```bash
qemu-system-x86_64 --version
# 关注官方 https://www.qemu.org/security/
```

### 2.2 关闭不用的设备

```bash
# 启动时显式禁用
-device none,?
# 或在 XML 里去掉 <input type='tablet'/> 等
```

### 2.3 关闭 9p / virtiofs

如果不需要文件共享，关掉 9p（出过多次 CVE）。

### 2.4 限制 QEMU 权限

libvirt 默认会：

- 把 QEMU 进程以 `qemu` 用户跑（非 root）
- seccomp 限制系统调用
- apparmor / selinux 沙箱

**检查**：

```bash
ps aux | grep qemu
# 应该看到 qemu:qemu，不是 root
```

## 3. sVirt：SELinux/AppArmor 给 QEMU 打标签

sVirt 是 libvirt 的一个特性：每个 VM 给唯一 SELinux label，保证 VM A 的进程不能写 VM B 的镜像。

### 3.1 默认配置

```bash
# 看当前 VM 的 label
ps -eZ | grep qemu
# system_u:system_r:svirt_t:s0:c87,c783 qemu-system-x86

# 看镜像文件 label
ls -laZ /var/lib/libvirt/images/
# system_u:object_r:svirt_image_t:s0:c87,c783 vm1.qcow2
```

不同 VM 的 `c87,c783` 部分不同，**SELinux 强制隔离**。

### 3.2 验证

```bash
# 用 VM A 进程去读 VM B 镜像
runcon system_u:system_r:svirt_t:s0:c87,c783 \
    qemu-img check /var/lib/libvirt/images/vm2.qcow2
# 期望：Permission denied
```

### 3.3 关闭 sVirt（不推荐）

```bash
# /etc/libvirt/qemu.conf
dynamic_ownership = 0
remember_owner = 0
security_driver = "none"
```

## 4. cgroup 隔离

```bash
# 看 VM 资源限制
systemd-cgtop | grep qemu
# 或
cat /sys/fs/cgroup/cpu,machine.slice/machine-qemu*.../cpu.cfs_quota_us

# 限制某个 VM
systemctl set-property libvirtd CPUQuota=200%
```

## 5. 网络隔离

### 5.1 nwfilter

libvirt 自带规则集：

```xml
<filterref filter='clean-traffic'/>
```

`clean-traffic` 阻止客户机伪 IP / 伪 MAC，避免 ARP 欺骗。

### 5.2 OVS 隔离

用 OVS flow 隔离 VM 间通信：

```bash
ovs-ofctl add-flow br0 "priority=100,in_port=1,actions=drop"
ovs-ofctl add-flow br0 "priority=100,in_port=2,actions=drop"
# 默认所有 VM 不能互访
```

### 5.3 客户机网络隔离（iptables）

```bash
iptables -A FORWARD -i virbr0 -o virbr0 -j DROP
# 客户机不能直接互访（NAT 隔离）
```

### 5.4 单 VM 限速

```bash
tc qdisc add dev vnet0 root tbf rate 100mbit burst 10mb latency 50ms
```

## 6. 控制面安全

### 6.1 libvirt 监听

```bash
# /etc/libvirt/libvirtd.conf
listen_tls = 1
listen_tcp = 0
tls_port = "16514"
auth_tls = "sasl"
```

### 6.2 TLS 证书

```bash
# 生成 CA + 证书
certtool --generate-privkey > cakey.pem
certtool --generate-self-signed --template ca.info --load-privkey cakey.pem --outfile cacert.pem
```

参考 [libvirt TLS 文档](https://libvirt.org/remote.html)。

### 6.3 SASL / Kerberos

```bash
saslpasswd2 -a libvirt peter
```

## 7. 磁盘加密

### 7.1 qcow2 加密

```bash
qemu-img create -f qcow2 -o encryption=on,key-secret=sec0 secret.qcow2 10G
```

XML：

```xml
<encryption format='luks'>
  <secret type='passphrase' uuid='...'/>
</encryption>
```

### 7.2 LUKS 全盘加密（推荐）

```xml
<disk type='file' device='disk'>
  <driver name='qemu' type='raw'/>
  <source file='/var/lib/libvirt/images/encrypted.raw'/>
  <target dev='vda' bus='virtio'/>
</disk>
```

VM 内用 `cryptsetup` 打开。

### 7.3 透传加密设备

生产常用：硬件加密卡 → VFIO → VM。

## 8. 安全启动（UEFI SecureBoot）

```bash
# 安装 OVMF + 微软 KEK
sudo apt install ovmf secureboot-db

# XML 启用
<os>
  <type arch='x86_64' machine='q35'>hvm</type>
  <loader readonly='yes' type='pflash' secure='yes'>/usr/share/OVMF/OVMF_CODE_4M.fd</loader>
  <nvram template='/usr/share/OVMF/OVMF_VARS_4M.fd'/>
</os>
```

## 9. 审计与监控

### 9.1 auditd

```bash
auditctl -w /var/lib/libvirt/images -p wa -k libvirt-images
auditctl -w /etc/libvirt -p wa -k libvirt-config
ausearch -k libvirt-images
```

### 9.2 libvirt 事件

```bash
virsh event --all --timeout 60
# 输出全部生命周期事件
```

### 9.3 行为监控（VM 内）

```bash
# 在 VM 内装 osquery / auditd
osqueryi
# SELECT * from processes;
```

## 10. 实战 checklist

- [ ] QEMU 装最新版（< 6 个月）
- [ ] 确认 sVirt 启用（`ps -eZ | grep qemu`）
- [ ] 关闭未用设备（9p、serial、tablet）
- [ ] libvirt 监听用 TLS，不要明文 TCP
- [ ] 共享存储加认证
- [ ] 关键 VM 启用 SecureBoot
- [ ] 监控 QEMU / libvirt 进程异常退出
- [ ] 定期 audit 镜像文件

## 11. 优劣对比速记

| 维度 | sVirt | cgroup | namespace | seccomp |
| --- | --- | --- | --- | --- |
| 文件访问隔离 | ✅ | ❌ | ❌ | ❌ |
| CPU/MEM 隔离 | ❌ | ✅ | ⚠️ | ❌ |
| 系统调用过滤 | ❌ | ❌ | ❌ | ✅ |
| 网络隔离 | ❌ | ❌ | ⚠️ | ❌ |
| 默认开 | ✅ | ✅ | ⚠️ | ⚠️ |

## 12. 小结

- VM 默认隔离来自硬件辅助 + sVirt + cgroup
- **保持 QEMU 新版本是头等大事**
- 控制面必须 TLS + SASL
- 生产推荐 LUKS 加密 + SecureBoot

## 13. 思考题

1. sVirt 防得了 VM 内攻击者直接读宿主机文件吗？防不了什么？
2. SecureBoot 能阻止 rootkit 吗？
3. 客户机能伪造 MAC/IP 攻击其他客户机吗？用什么隔离方案？
4. VM 逃逸 CVE 通常出现在哪里？
