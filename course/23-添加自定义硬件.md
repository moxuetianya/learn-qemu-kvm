# 23 · 添加自定义硬件实战

> 「给虚拟机加个硬件」在 QEMU 里有三个层次：加一个**已有设备**、**热插**进运行中的
> VM、以及**开发一个全新设备**。这章讲前两个，第三个留给第 24 章。

## 学习目标

- 分清「设备（`-device`）」「后端对象（`-object`）」「总线（bus）」三者的关系
- 会用 `-device help` / `-device TYPE,help` 查设备及其参数
- 能用 monitor / QMP 给运行中的 VM 热插设备，并知道 guest 侧需要什么
- 知道 libvirt 里给任意 `-device` 开后门的方法
- 会加：第二个网卡、virtio-rng、ivshmem、vIOMMU、直通设备

## 1. 先理清概念：设备、后端、总线

QEMU 把「一个功能」常拆成三块：

```
   guest 看到的硬件         QEMU 里的"设备"          宿主机上的"后端"
   ─────────────────       ──────────────          ──────────────
   网卡 (virtio-net-pci)  ← -device 前端          -netdev tap/user
   磁盘 (virtio-blk-pci)  ← -device 前端          -drive / -blockdev
   串口 (pci-serial)      ← -device 前端          -chardev
   加密 (virtio-crypto)   ← -device 前端          -object cryptodev-...
   随机数 (virtio-rng-pci) ← -device 前端          -object rng-random
```

- **`-device`**：客户机能"看见"的那个硬件
- **`-netdev` / `-drive` / `-chardev` / `-object`**：数据在宿主机的去向（后端）
- **bus**：设备挂在哪条总线上（`pcie.0`、`pci.0`、`isa.0`、`virtio-bus`…）

> 记住：`-device` 只是"插卡"，后端才决定数据怎么流。第 04 章的
> `-drive` + `-device` 就是这套模型。

## 2. 认识设备：`-device help`

```bash
# 列出所有可用设备
qemu-system-x86_64 -device help

# 看某设备的全部参数（最常用的自省手段）
qemu-system-x86_64 -device virtio-net-pci,help
# virtio-net-pci.netdev=netdev       ← 属性名.类型
# virtio-net-pci.mac=macaddr
# virtio-net-pci.mq=on/off
# ...

# 看后端对象
qemu-system-x86_64 -object help
# 看总线
qemu-system-x86_64 -machine q35 -device help   # 设备列表随机型变
```

参数规则：`-device <type>[,<prop>=<val>]...`，其中 `id=` 给这个设备起名，
后续（热插、QMP、`-global`）用它引用。

## 3. 一类"什么都加"的设备清单

| 想要的硬件 | 命令行 | 备注 |
| --- | --- | --- |
| 熵源（免卡顿） | `-device virtio-rng-pci` | 现代 VM 默认该有 |
| 气球（动态内存） | `-device virtio-balloon` | 配合 guest 驱动回收内存 |
| 第二块 NVMe | `-device nvme,serial=nvme1,drive=d1` | 需配 `-drive` |
| 看门狗 | `-device i6300esb` | guest 看门狗超时可复位 |
| 共享内存 | `-device ivshmem-plain,memdev=shm0` | 配 `-object memory-backend-*` |
| 多串口 | `-device pci-serial,chardev=ser2` | 配 `-chardev` |
| 文件共享 (9p) | `-device virtio-9p-pci,fsdev=fs0,mount_tag=host` | 配 `-fsdev` |
| 文件共享 (virtiofs) | `-device vhost-user-fs-pci,chardev=...,tag=host` | 需 virtiofsd |
| vIOMMU | `-device intel-iommu,intremap=on,caching-mode=on` | 需 `kernel-irqchip=split` |
| PCI 直通 | `-device vfio-pci,host=0000:01:00.0` | 见 lab07 |
| TPM | `-device tpm-tis,tpmdev=tpm0` | 配 `-tpmdev` |
| 随机数/加密后端 | `-object rng-random,filename=/dev/urandom,id=rng0` | `-device` 引用它 |

## 4. 后端对象：`-object` 与设备配对

有些功能必须先建一个**后端对象**，再让设备引用：

```bash
# 1) virtio-rng 需要一个熵源后端
-object rng-random,filename=/dev/urandom,id=rng0 \
-device virtio-rng-pci,rng=rng0

# 2) ivshmem 需要一块共享内存后端
-object memory-backend-file,id=shm0,size=4M,mem-path=/dev/shm/shm0,share=on \
-device ivshmem-plain,memdev=shm0

# 3) iothread：把某设备的后端 IO 挪出 main 线程
-object iothread,id=io1 \
-device virtio-blk-pci,drive=d0,iothread=io1
```

用 `-object help` 看类型，用 monitor 的 `info qom-tree` 看对象树。

## 5. 热插拔：给运行中的 VM 加设备

QEMU 支持把设备**热插**进去，不用重启。三条路，本质一样：

### 5.1 monitor 交互式

```
(qemu) device_add virtio-net-pci,id=net1,netdev=n1
# 不行：后端 netdev 也要先热插
(qemu) netdev_add user,id=n1
(qemu) device_add virtio-net-pci,id=net1,netdev=n1
(qemu) info qtree | grep -A2 virtio-net
```

### 5.2 QMP（脚本/自动化用）

```bash
echo '{"execute":"qmp_capabilities"}' | \
  socat - UNIX-CONNECT:/tmp/qmp.sock
# {"execute":"netdev_add","arguments":{"type":"user","id":"n1"}}
# {"execute":"device_add","arguments":{"driver":"virtio-net-pci","id":"net1","netdev":"n1"}}
```

或者用 libvirt 代发：

```bash
virsh qemu-monitor-command myvm --pretty \
  '{"execute":"device_add","arguments":{"driver":"virtio-rng-pci","id":"rng1"}}'
```

### 5.3 guest 侧前提

热插不是"免费"的，客户机必须配合：

- x86 上 PCI 热插靠 **ACPI**（`acpiphp`）或 **PCIe native**（`pciehp`）
- 需要客户机内核加载对应模块；很多 cloud 镜像默认有
- 内存/CPU 热插还要求固件、机型、客户机都支持（q35 + ACPI）

```bash
# guest 里看热插是否生效
lspci | grep -i virtio
dmesg | tail
```

> 生产建议：**能规划好就别热插**。热插适合临时加盘、加网卡、动态扩缩。

## 6. 在 libvirt 里加任意设备

libvirt 有自己的 XML 模型，但设备类型覆盖不全。两个办法：

1. 优先用原生 XML（`<interface>` `<hostdev>` `<rng>` `<shmem>` 等）
2. 实在没有，用 `<qemu:commandline>` 塞原始 `-device`：

```xml
<domain type='kvm' xmlns:qemu='http://libvirt.org/schemas/domain/qemu/1.0'>
  ...
  <qemu:commandline>
    <qemu:arg value='-object'/>
    <qemu:arg value='rng-random,filename=/dev/urandom,id=rng0'/>
    <qemu:arg value='-device'/>
    <qemu:arg value='virtio-rng-pci,rng=rng0,id=rng0'/>
  </qemu:commandline>
</domain>
```

冲突处理：如果 libvirt 已经加了同名设备/`id`，会生成重复定义而报错。
用 `virsh dumpxml` + `ps -ef | grep qemu` 对照 libvirt 实际拼出的命令行。

## 7. 实战

### 7.1 加第二块网卡（命令行）

```bash
qemu-system-x86_64 -machine q35,accel=kvm -m 1G \
    -netdev user,id=n0 -device virtio-net-pci,netdev=n0 \
    -netdev user,id=n1 -device virtio-net-pci,netdev=n1 \
    -display none -monitor stdio
(qemu) info network
```

### 7.2 加 virtio-rng（后端 + 前端）

```bash
qemu-system-x86_64 -machine q35,accel=kvm -m 1G \
    -object rng-random,filename=/dev/urandom,id=rng0 \
    -device virtio-rng-pci,rng=rng0 \
    -display none -monitor stdio
(qemu) info qtree | grep -i rng
```

guest 里 `cat /dev/hwrng | head -c 16 | xxd` 能拿到随机数。

### 7.3 加 ivshmem（共享内存）

```bash
# 宿主机准备共享内存文件
dd if=/dev/zero of=/dev/shm/shm0 bs=1M count=4

qemu-system-x86_64 -machine q35,accel=kvm -m 1G \
    -object memory-backend-file,id=shm0,size=4M,mem-path=/dev/shm/shm0,share=on \
    -device ivshmem-plain,memdev=shm0 \
    -display none -monitor stdio
(qemu) info pci | grep -i ivshmem
```

### 7.4 加 vIOMMU（直通必备）

```bash
qemu-system-x86_64 \
    -machine q35,accel=kvm,kernel-irqchip=split \
    -device intel-iommu,intremap=on,caching-mode=on \
    -m 2G -display none -monitor stdio
(qemu) info qtree | grep -i iommu
```

### 7.5 热插一块 virtio-blk

```bash
# 起 VM（示例从略），在 monitor 里：
(qemu) drive_add 0 if=none,file=/tmp/extra.qcow2,format=qcow2,id=d1
(qemu) device_add virtio-blk-pci,drive=d1,id=blk1
(qemu) info block
```

## 8. 优劣对比：三种"加硬件"方式

| 方式 | 何时用 | 优点 | 缺点 |
| --- | --- | --- | --- |
| `-device`（启动时） | 固定配置 | 简单、可复现 | 改了要重启 VM |
| `device_add`（热插） | 临时/动态 | 不停机 | 依赖 guest ACPI/驱动 |
| 写新设备（第 24 章） | 有特殊需求 | 完全定制 | 要改 QEMU 源码 |

## 9. 小结

- 一个功能常拆成 **前端设备（`-device`）+ 后端（`-object`/`-netdev`/`-drive`）**
- 自省三板斧：`-device help`、`-device TYPE,help`、`-object help`
- 热插用 `device_add`（monitor / QMP），前提是 guest 支持 ACPI/PCIe 热插
- libvirt 覆盖不到的设备，用 `<qemu:commandline>` 塞原始参数
- 常规加成：virtio-rng、virtio-balloon、第二网卡、ivshmem；直通用 vfio + vIOMMU

## 10. 思考题

1. 为什么 `device_add` 一块网卡，通常要先把 `netdev` 热插进去？
2. ivshmem 的"共享内存"是 VM 和谁共享？三台 VM 能不能同时映射同一块？
3. 为什么 vIOMMU 常要求 `kernel-irqchip=split`？
4. 热插一块 PCI 卡，guest 里什么都没出现，你会按什么顺序排查？

<details>
<summary>参考答案（先自己想再看）</summary>

1. `-device` 只是前端"卡"，数据必须流向后端；网卡在 realize 时要用 `netdev` 属性指向一个已存在的后端对象，找不到就 realize 失败。启动时命令行也要求 `-netdev` 先定义，热插同理必须先 `netdev_add` 建好后端再 `device_add` 引用。顺序颠倒就插不进去。
2. ivshmem 共享的是宿主机上的一块内存（`memory-backend-file` 映射的 `/dev/shm` 文件等），guest 通过 BAR 中的共享窗口把它映射进来，实现 VM 之间、VM 与宿主机进程之间的共享。多台 VM 可以同时映射同一块：只要引用相同的 `mem-path` 后端，它们就共享同一段物理内存。这正是 ivshmem 用于跨 VM 通信/零拷贝的场景。
3. intel-iommu 的 interrupt remapping（`intremap=on`）需要 QEMU 能拦截并改写中断路由，而传统的 in-kernel irqchip 把中断整体放在 KVM 内核里，vIOMMU 插不上手。`kernel-irqchip=split` 把大部分中断芯片放到用户态，QEMU 才能实现重映射。所以开 `intremap` 时通常要求 `split`。
4. 按层次排查：先看 QEMU 侧 `device_add` 是否成功（monitor 无报错、`info qtree` 里有设备），再确认 guest 是否加载了热插控制器（`acpiphp`/`pciehp`，`dmesg` 有无 ACPI hotplug 事件），然后检查 ACPI 中断路由与槽位是否可达，最后尝试手动 rescan（`echo 1 > /sys/bus/pci/rescan`）。最常见原因是 guest 缺 `acpiphp`/`pciehp`，或机型/固件不支持 PCI 热插。

</details>
